===========================================================

Every fillable field in the 6-slide brochure, in PAYLOAD format (same shape as
smoke_test.py). 50 fields total.

Source: Hackathon_Brochure_Template.pptx, text extracted slide by slide.

NOTE ON NAMING
  Slide 1 reuses the six tags the presentation already uses, so a single
  extraction manifest can feed both documents. Everything below slide 1 is
  brochure-only.

NOTE ON WHAT COUNTS AS A FIELD
  Most fields appear as "[ bracketed prompts ]" in the template. Four do not --
  PROBLEM_STATEMENT, AUDIENCE_DESCRIPTION, and the two guidance paragraphs --
  they are written as instructional prose that the author overwrites. They are
  included because they must be replaced; they will need the bracket-to-tag
  mapping added by hand or the whole paragraph replaced.

NOTE ON IMAGES
  Three placeholders are images, not text, and cannot be filled by
  replaceAllText:
    slide 1  [Your logo goes here]
    slide 3  [Add a diagram of the architecture of the solution]
    slide 5  [ Insert screenshot, GIF, or video link of the agent in action ]
  The third is listed below as DEMO_EVIDENCE because a link is acceptable there;
  the first two need createImage requests instead.

ORIGINAL TEMPLATE TEXT -> TAG
=============================

The template does not contain {{TAGS}} yet. These are the literal strings to map,
in the same form as PLACEHOLDER_MAP in setup_template.py. Note that several are
identical strings repeated across the slide -- "[ what they need from the agent ]"
appears three times, "[ XX% ]" three times -- so replaceAllText cannot tell them
apart. Those need distinct text in the master template before they can be filled
individually.

  [ Agent Name ]                                    -> {{AGENT_NAME}}
  [ One-line tagline: ... ]                         -> {{TAGLINE}}
  [ names ]                                         -> {{TEAM_NAMES}}
  [ date ]                                          -> {{DATE}}
  [ draft / ready for review / final ]              -> {{STATUS}}
  [ e.g., Retail, Supply Chain, Finance ]           -> {{INDUSTRY}}
  [ Persona 1 ]                                     -> {{PERSONA_1_NAME}}
  [ Persona 2 ]                                     -> {{PERSONA_2_NAME}}
  [ Persona 3 ]                                     -> {{PERSONA_3_NAME}}
  [ what they need from the agent ]         x3      -> {{PERSONA_n_NEED}}   AMBIGUOUS
  [ Capability 1: name + one-line description ]     -> {{CAPABILITY_1}}
  [ Capability 2: name + one-line description ]     -> {{CAPABILITY_2}}
  [ Capability 3: name + one-line description ]     -> {{CAPABILITY_3}}
  [ e.g., Gemini, Claude, GPT ]                     -> {{TECH_MODEL}}
  [ e.g., BigQuery, Postgres, CRM ]                 -> {{TECH_DATA_SOURCES}}
  [ e.g., MCP servers, APIs, retrieval ]            -> {{TECH_TOOLS}}
  [ e.g., Cloud Run, ADK, local ]                   -> {{TECH_HOSTING}}
  [ Blocker name ]                          x3      -> {{BLOCKER_n_NAME}}   AMBIGUOUS
  [ how the agent removes it ]               x3     -> {{BLOCKER_n_FIX}}    AMBIGUOUS
  [ XX% ]                                    x3     -> {{IMPACT_n_VALUE}}   AMBIGUOUS
  [ metric it improves ]                     x3     -> {{IMPACT_n_METRIC}}  AMBIGUOUS
  [ KPI name ]                               x2     -> {{KPI_n_NAME}}       AMBIGUOUS
  [ how it's calculated ]                    x2     -> {{KPI_n_FORMULA}}    AMBIGUOUS
  [ goal number ]                            x2     -> {{KPI_n_TARGET}}     AMBIGUOUS
  [ Insert screenshot, GIF, or video link ... ]     -> {{DEMO_EVIDENCE}}
  [ Sample interaction: "User asked ___ ..." ]      -> {{DEMO_SAMPLE}}
  [ What was mocked or simulated ... ]              -> {{ASSUMPTION_MOCKED}}
  [ What's explicitly out of scope ... ]            -> {{ASSUMPTION_OUT_OF_SCOPE}}
  [ Known edge cases or risks ... ]                 -> {{ASSUMPTION_RISKS}}
  [ Repo / codebase link ]                          -> {{LINK_REPO}}
  [ Design doc / PRD link ]                         -> {{LINK_DESIGN_DOC}}
  [ Slide deck / demo video link ]                  -> {{LINK_DECK}}
  [ Any other supporting material ]                 -> {{LINK_OTHER}}
  [ What does this team need to move ... ]          -> {{NEXT_STEPS}}
  [ Team contact name / email ]                     -> {{CONTACT}}

  (no bracketed text) "What's broken today for ..." -> {{PROBLEM_STATEMENT}}
  (no bracketed text) "List the specific roles ..." -> {{AUDIENCE_DESCRIPTION}}

The 13 AMBIGUOUS entries are the blocker: 8 distinct literals cover 21 slots.
Fill them by hand in the master deck ({{PERSONA_1_NEED}}, {{PERSONA_2_NEED}}, ...)
rather than trying to normalize them automatically.
